Paradigmas de programación y el lugar del funcional

En Scheme estábamos obligados a pensar funcionalmente. En Kotlin, elegimos cuándo hacerlo.

Repaso: Lo que ya sabemos con Scheme

¿Qué es val en Kotlin?

En Kotlin, val se usa para declarar una referencia inmutable:
 una vez asignado un valor, no se puede volver a asignar.

📌 Ejemplo:

val x = 10

x = 20 // ❌ Error: no se puede reasignar una variable `val`

¿Inmutable significa constante?

No exactamente. val no hace que el contenido del objeto sea inmutable,
 sólo que la referencia no puede cambiar.

val lista = mutableListOf(1, 2, 3)

lista.add(4) // ✅ permitido

lista = mutableListOf(5, 6) // ❌ no permitido

Tail 

Kotlin permite optimizar recursiones terminales:

tailrec fun factorial(n: Int, acc: Int = 1): Int =

    if (n <= 1) acc else factorial(n - 1, acc * n)

Evita desbordes de pila y permite escribir funciones sin bucles.

map y filter: transformación funcional de listas

Las funciones map y filter son la base de la transformación declarativa de colecciones.

val numeros = listOf(1, 2, 3, 4, 5, 6)

val pares = numeros.filter { it % 2 == 0 }    // [2, 4, 6]

val cuadrados = numeros.map { it * it }       // [1, 4, 9, 16, 25, 36]

Se pueden encadenar:

val resultado = numeros

    .filter { it > 3 }

    .map { it * 10 }  // [40, 50, 60]

El código expresa qué queremos sin detallar cómo hacerlo.

▶ Problema para investigar: ¿Cómo reescribirías este código con bucles imperativos? ¿Cuál es más claro?

fold y reduce: acumuladores funcionales

Estas funciones permiten reducir una colección a un solo valor:

val suma = listOf(1, 2, 3).reduce { acc, n -> acc + n } // 6

val factorial = listOf(1, 2, 3, 4).fold(1) { acc, n -> acc * n } // 24

Diferencia clave:

●

●

reduce: usa el primer elemento como acumulador inicial

fold: permite especificar un valor inicial

val letras = listOf("a", "b", "c").fold("→") { acc, letra -> "$acc $letra" }

// → a b c

▶ Problema para investigar: ¿Por qué fold es más seguro que reduce en listas vacías

groupBy y partition: reorganizar colecciones

Agrupan elementos según una clave:

val personas = listOf("Ana", "Axel", "Bea", "Bruno")

val agrupado = personas.groupBy { it.first() }

// {A=[Ana, Axel], B=[Bea, Bruno]}

Parten en dos listas:

val (positivos, negativos) = listOf(-3, -2, 5, 6).partition { it > 0 }

// positivos = [5, 6], negativos = [-3, -2]

Herramientas poderosas para categorizar y filtrar datos.

▶ Problema para investigar: ¿Cómo usarías groupBy para agrupar palabras por su longitud?

asSequence

val resultado = (1..1_000_000)

    .filter { it % 2 == 0 }

    .map { it * 2 }

    .take(5) // Toma los primeros 5

Sin asSequence(), filtra y mapea todos los millones de números,

aunque solo queríamos los primeros 5.

Con asSequence():

val resultado = (1..1_000_000).asSequence()

    .filter { it % 2 == 0 }

    .map { it * 2 }

    .take(5)

    .toList() // convierte en lista

▶ Problema para investigar: Medir diferencia de tiempo con y sin asSequence() usando System.currentTimeMillis().

flatMap: aplanar y transformar

Cuando cada elemento se transforma en una colección, flatMap permite aplanar el resultado.

val lineas = listOf("uno dos", "tres cuatro")

val palabras = lineas.flatMap { it.split(" ") }

// [uno, dos, tres, cuatro]

Combina map + flatten en una sola operación eficiente.

🧠 Ideal para transformar listas de listas, o resultados encadenados.

▶ Problema para investigar: ¿Qué sucede si usás map en vez de flatMap en el ejemplo anterior?

zip: combinar listas en pares

Une dos listas en una sola colección de pares:

val nombres = listOf("Ana", "Beto", "Caro")

val edades = listOf(21, 30, 27)

val personas = nombres.zip(edades)

// [(Ana, 21), (Beto, 30), (Caro, 27)]

También se puede usar con una transformación:

val personasStr = nombres.zip(edades) { n, e -> "$n tiene $e años" }

▶ Problema para investigar: ¿Qué pasa si las listas tienen tamaños distintos?

Librerías y frameworks para programación funcional

🔷 1. Arrow

La librería funcional más completa para Kotlin.
 Provee tipos como Either, Option, Validated, Try, y abstracciones como Functor, Applicative, Monad, raise.either, 
etc.

🔷 2. Kotlinx.coroutines

Concurrencia funcional con coroutines.
 Permite flujos inmutables (Flow, StateFlow, SharedFlow) y composición estructurada de asincronía sin callbacks.

🔷 3. Reactor Kotlin Extensions / RxKotlin

Extensiones reactivas para flujos y transformación de datos en tiempo real.
 Enfocado en flujos continuos (Flux, Mono) y composición de pipelines funcionales.

🔷 4. Kotest (antes KotlinTest)

Librería para testing funcional y declarativo.
 Soporta propiedades (property testing), matchers expresivos y testing puro sin mocks imperativos.

Estas herramientas permiten extender la programación funcional más allá de las colecciones: hacia validación, 
concurrencia, lógica de dominio y testing.

¿Qué es Arrow?

Arrow es una biblioteca funcional para Kotlin que proporciona herramientas y abstracciones para aplicar conceptos de programación 
funcional en proyectos reales. Su objetivo es complementar el lenguaje Kotlin con estructuras y patrones funcionales que permiten 
escribir código más seguro, expresivo y mantenible.

Características principales:

●

Tipos de datos funcionales: Option, Either, Validated, Try, entre otros.

● Manejo de efectos: Control de efectos secundarios y concurrencia mediante coroutines.

●

●

Optics: Manipulación de estructuras de datos inmutables de forma segura y concisa.

Resiliencia: Patrones para construir aplicaciones robustas y tolerantes a fallos.

¿Qué es Arrow?

Aunque Kotlin ofrece soporte para programación funcional, Arrow amplía estas capacidades y proporciona herramientas adicionales 
que facilitan la adopción de este paradigma.

Ventajas de usar Arrow:

● Manejo seguro de errores: Evita el uso de excepciones mediante tipos como Either y Validated.

●

●

●

Código más expresivo: Utiliza combinadores funcionales (map, flatMap, fold) para transformar y componer operaciones.

Inmutabilidad: Fomenta el uso de estructuras de datos inmutables, reduciendo efectos secundarios.

Composición de funciones: Facilita la creación de funciones modulares y reutilizables.
