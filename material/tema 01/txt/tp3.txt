Enunciado 

Dominio: Desarrollo de una mini-biblioteca de calculadora y su suite de tests unitarios. 

¿Por qué es relevante? En la industria, los tests unitarios permiten detectar errores 
temprano, documentar el comportamiento esperado y refactorizar con seguridad; pytest es 
una herramienta estándar para automatizar estas verificaciones en proyectos Python. 

¿Qué van a construir? 

Un repositorio con: 
- un módulo `calculator` que implementa operaciones matemáticas comunes (funciones 
puras y determinísticas), 
- una suite de tests con `pytest` (incluyendo casos borde y manejo de excepciones), 
- autograding con GitHub Actions y cobertura mínima.

REQUISITOS TÉCNICOS 

ESTRUCTURA: 

- [ ] `add(a: float, b: float) -> float` 
- [ ] `sub(a: float, b: float) -> float` 
- [ ] `mul(a: float, b: float) -> float` 
- [ ] `div(a: float, b: float) -> float`

  - Debe **lanzar** `ZeroDivisionError` si `b == 0`. 
- [ ] `pow_(a: float, b: float) -> float` (usar nombre `pow_` para no pisar built-in `pow`) 
- [ ] `sqrt(x: float) -> float` 
  - Debe lanzar `ValueError` si `x < 0`. 
- [ ] `mean(values: list[float]) -> float` 
  - Debe lanzar `ValueError` si la lista está vacía. 

Tests: 

- [ ] 1 archivo de tests por grupo (mínimo 4 archivos; recomendado: 1 por tema). 
- [ ] Usar `pytest` con: 
  - [ ] asserts claros 
  - [ ] tests de excepciones (`pytest.raises`) 
  - [ ] al menos 1 test parametrizado (`@pytest.mark.parametrize`) 
- [ ] Cobertura mínima: **≥ 80%** sobre `src/`. 

Git: 

- [ ] Realizar **≥ 6 commits** significativos (uno por ejercicio como mínimo). 
- [ ] No commitear entornos virtuales (`.venv/`) ni caches.
