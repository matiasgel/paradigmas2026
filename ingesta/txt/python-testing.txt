Testing de software

● Es un proceso que busca verificar la exactitud, 

integridad y calidad de un software.

● Incluye una serie de actividades que buscan encontrar 
errores y fallas en el software previo a que lleguen al 
usuario.

● Los errores en el software no identificados a tiempo 

pueden ser sumamente costosos en términos 
monetarios o incluso llevar a pérdidas de vidas 
humanas.

Testing de software

►

►

Las pruebas se realizan sin 
conocimiento del funcionamiento 
interno del software, se preparan un 
juegos de entradas y se observan si las 
salidas siguen las especificaciones.

Las pruebas se realizan conociendo la 
estructura interna del software. Los 
juegos de datos de entrada se 
seleccionan en base a este 
conocimiento y suelen apuntar a 
probar características específicas de 
su estructura.

En esta clase vamos a recorrer algunas de las abstracciones de python 
para dar soporte a pruebas unitarias :

Test case (caso de prueba)

Un caso de prueba es una prueba de unidad individual. Verifica la respuesta de un conjunto de 
sentencias  a ciertos datos de entrada. El framework unittest provee una clase TestCase que 
puede ser heredada para crear nuevos casos de prueba.

test suite (conjunto de pruebas)

Un test suite es una colección de casos  de pruebas y/o otros test suite. Se utiliza para ejecutar 
pruebas en conjunto..

test runner

Un test runner es un componente que orquesta la ejecución de test y provee una salida al 
usuario. Puede tener una interfaz gráfica o textual que muestre el resultado de la ejecución de 
un conjunto de pruebas.

Python – sentencia with

• La sentencia with fue pensada para mejorar el manejo 

de excepciones.  

• Podemos analizar su uso en base a un ejemplo.

• Muchas veces al ejecutar código que puede ser 
factible de lanzar excepciones necesito realizar 
tareas para preparar la ejecución.

• Al terminar la ejecución del código requiero 

realizar un conjunto de tareas para no dejar al 
sistema en un estado propenso a errores. 
• En el ejemplo realizó un query sobre una 
supuesta conexión de base de datos.

• La sentencia with me permite encapsular el 

código en una clase que contiene los métodos 
___enter__ y __exit__ .  Los objetos de este tipo se 
llaman contextmanager.

• Al iniciar la ejecución del bloque with  el 

intérprete llama a al método __enter__ del 
contextmanager. 

• Al terminar el bloque se llama a __exit__ incluso si 

se lanzó una excepción.

La clase TestCase - 
fixtures

❖ setUp():  Este método es llamado antes de la ejecución de 

cada  método test. Aquí se preparan los datos necesarios a 
utilizar en el test.

❖ tearDown(): Este método es llamado al finalizar la ejecución 
de cada método y es utilizado para limpiar las instancias 
utilizadas en el método de prueba.  Se ejecuta incluso si una 
excepción es lanzada durante la ejecución de la prueba. 
❖ setUpClass(): este método debe ser implementado como 

método de clase y se ejecuta al inicio de todas las 
prueabas de la clase. 

❖ tearDownClass(): este método se ejecuta al finalizer todas 

las pruebas de una clase.
